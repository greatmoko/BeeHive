# BeeHive

BeeHive 是面向 Windows 的本地 AI 桌面工作台，将日常对话、项目 Agent、定时任务和原型设计放在同一套界面中。应用使用 Python、PySide6 和 Qt WebEngine，Agent 执行基于 Deep Agents / LangGraph，模型通过用户配置的 API 接入。

当前源码版本为 **0.2.2**，以 `pyproject.toml` 为准。

- 源码仓库：[greatmoko/BeeHive](https://github.com/greatmoko/BeeHive)
- 许可证：[MIT](LICENSE)
- 发布方式：提供源码，不提供预编译 EXE。

## 功能概览

| 入口 | 主要用途 |
| --- | --- |
| **TokBee** | 多会话聊天、角色提示词、图片和文档附件、流式回复 |
| **WokBee** | 围绕独立项目执行任务，读写文件、运行命令、复用经验和脚本 |
| **AutoBee** | 按 Cron 调度文本、脚本或 WokBee 项目任务，查看执行记录和推送结果 |
| **DeziBee** | 用对话迭代需求、PRD 和网页原型，预览并导出单文件 HTML |
| **AIConfig** | 管理厂商、模型、角色、运行参数、记忆、Skills、凭据、MCP 和消息网关 |
| **Settings** | 通用设置，包括聊天清理、项目清理和运行环境信息 |

项目执行围绕“探索 → 总结经验 → 固化脚本 → 再次运行”组织。已有脚本可以减少重复模型调用；实际用量取决于管线是否包含 AI 步骤、是否重新规划以及失败后的处理，不保证所有重复任务都零 Token。

## 环境要求

| 项目 | 要求 |
| --- | --- |
| 操作系统 | 主要面向 Windows 10 / 11；其他平台未完成相同范围的验证 |
| Python | 3.11 或更高，使用独立虚拟环境 |
| 模型服务 | 可访问的模型 API，以及对应的 API Key |
| 命令执行 | Windows 优先使用 PowerShell 7（`pwsh`），其次为 Windows PowerShell |
| 可选运行时 | 执行相应脚本或 MCP 服务时，需自行准备 Python、Node.js 或其他工具 |

主要依赖包括 PySide6、Deep Agents、LangGraph、langchain-openai、APScheduler、httpx、PyMuPDF、Office 文档解析库、cryptography 和 keyring。完整依赖见 `requirements.txt` 与 `pyproject.toml`。

## 安装与启动

在 PowerShell 中执行：

```powershell
git clone https://github.com/greatmoko/BeeHive.git
cd BeeHive

python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip check
```

直接使用虚拟环境解释器，无需先激活环境，也无需修改 PowerShell 的脚本执行策略。

**正常启动：**双击根目录的 `start.vbs`，或在 PowerShell 中执行：

```powershell
.\start.vbs
```

启动器固定使用 `.venv\Scripts\pythonw.exe`，以项目目录为工作目录，不显示命令行窗口；环境缺失时会弹出提示。

**排查启动问题：**使用控制台运行，查看错误信息：

```powershell
.\.venv\Scripts\python.exe -B main.py
```

启动链路为 `main.py → beehive.__main__ → Application → MainWindow`。旧的 `tokbee` 包启动方式已不适用于当前目录结构。

## 首次配置

1. 打开 **AIConfig → 厂商设置**，添加厂商，填写 API Host 和 API Key。
2. 拉取模型列表，或手动添加模型 ID；启用需要使用的模型。
3. 核对模型的上下文窗口、输出上限、图片能力及接口协议，设置默认模型。
4. 在 **TokBee 设置** 中配置新会话默认参数，在 **WokBee 设置** 中确认默认模型、工作目录和审批策略；在 **DeziBee 设置** 中确认工作目录、审批与执行限制，设计模型在需求聊天输入栏选择。
5. 在 **系统运行设置** 中检查运行环境、工具和模型超时；按需添加 Skills、MCP 或凭据。
6. 先用一个简单对话验证模型，再创建测试项目执行文件或命令操作。

厂商目录提供 OpenAI、Gemini、DeepSeek、GLM、通义千问、Kimi 等预置连接信息，也支持自定义厂商。模型列表需要用户拉取或添加，预置厂商不等于已配置可用模型。

模型配置包含 Chat Completions 与 Responses 协议选项。应按实际服务能力选择；兼容接口不代表支持全部工具调用、图片、推理或流式能力。

## TokBee：日常对话

- 管理多个独立会话，选择模型和 AI 角色，调整会话参数。
- 支持流式回复、Markdown 展示和上下文用量提示。
- 图片附件支持 JPG、JPEG、PNG、GIF、WebP、BMP；图片理解需要模型支持。
- 文档附件支持 TXT、Markdown、PDF、DOCX、XLSX、PPTX，按文件类型提取内容供模型使用。
- 附件会复制到本地会话附件目录，供历史消息继续引用。

文档解析不保证保留原始排版，也不保证识别扫描 PDF 的内容。发送文件前应确认所选模型及服务允许处理该类内容。

## WokBee：项目执行与经验复用

每个项目有独立的名称、目标、文件目录和事件记录。项目切换不会直接销毁正在执行的工作区，不同项目可在后台继续运行。

### 执行方式

| 模式 | 行为 |
| --- | --- |
| **交互模式** | 围绕用户输入使用 Agent 工具，不执行经验管线；可读取和更新相关记忆、项目经验 |
| **运行模式** | 围绕项目目标执行，结合已有经验、脚本和管线处理可重复任务 |

Agent 可使用文件读写与搜索、本机命令、联网工具、Skills 和 MCP。具体可用工具由配置、权限及所连接的服务决定。桌面交互中的文件写入、命令执行等操作按审批配置处理；项目外目录访问需配置或申请附加目录权限。

可以暂停或终止执行。系统对工具和模型调用分别设置超时，部分工具支持单次覆盖默认等待时长；这些机制不保证撤销已经完成的文件修改或外部操作。

### 新项目目录

默认工作根目录为 `~/BeeHive/WokBee/`，可在 WokBee 设置中修改。每个新项目使用以下结构：

```text
<项目目录>/
├── .project/
│   ├── project.json       # 项目配置，由应用维护
│   └── Agent.md           # 用户自定义项目规则，新建时为空
├── uploads/              # 用户上传资料，长期保留
├── output/               # 最终交付物
├── memory/
│   ├── events.jsonl      # 应用追加的轮次事件记录
│   ├── exp_*.md          # 项目经验，按实际运行生成
│   ├── pipeline.json     # 有序执行管线，按需生成
│   ├── <复用脚本>        # 固化的脚本
│   └── <技能名>/         # 使用过的 Skills 快照
└── archives/             # 归档快照，禁止 Agent 访问
```

临时脚本和中间材料可出现在项目根目录，最终产物放入 `output/`。`memory/events.jsonl` 由应用管理，Agent 不应改写。

旧项目可能保留根目录 `project.json`、`scripts/`、`runs/`、`workspace/` 或旧会话记忆文件。当前实现保留兼容读取，不应按新结构手工批量搬移或删除旧目录。

### 归档规则

| 操作 | 归档并清理 | 保留 |
| --- | --- | --- |
| 普通归档 | `output/` 的内容、项目根目录本轮散落的普通文件 | 上传资料、记忆、项目配置及旧版目录；`output/README.txt` 保留 |
| 清空经验归档 | 普通归档内容，加上 `memory/` 中的经验、管线、复用脚本和技能快照等 | `memory/events.jsonl`、旧版 `memory/session_memory.md`、上传资料及项目配置 |

事件日志不会因归档自动清空。归档涉及磁盘写入和文件移动，操作前应备份重要项目。

## DeziBee：需求与原型设计

DeziBee 使用独立的设计模式，不执行 WokBee 经验管线，也不注入 WokBee 项目经验。默认工作根目录为 `~/BeeHive/DeziBee/`，可在 DeziBee 设置中修改。

基本流程：新建需求 → 输入需求并上传参考材料 → 与 Agent 讨论或修改 → 预览原型和 PRD → 按需导出。

原型工作台包含页面导航、画布卡片、交互关系和关联 PRD，可在本机浏览器中预览、编辑 PRD。同一需求支持另起对话；新对话不继承旧聊天上下文，但仍可读取该需求当前的 Demo 和 PRD。

需求目录中的主要内容：

- `demo/index.html`：原型入口，其中的 `WORKBENCH_DATA` 保存原型与主要 PRD 数据。
- `demo/assets/`：原型素材；`demo/css/`、`demo/js/` 为模板框架资源。
- `prd/`：补充需求文档。
- `uploads/`：上传的参考资料。
- `dezibee.json`：应用维护的需求及交互元数据。

设计工作区通过本地服务预览和编辑，可导出单文件 HTML 供分享。导出结果是静态只读原型，不包含本地编辑服务；资源缺失或外部链接可能影响离线效果，应检查导出提示并实际打开验证。

## AutoBee：定时任务

支持文本、Python / JavaScript 脚本和 WokBee 项目三类任务。文本任务可固定输出或调用 AI 生成；任务可设置 Cron 表达式、启停、立即执行并查看运行记录，也可让 AI 辅助生成调度配置。

脚本任务依赖本机对应的运行时。任务结果可按配置推送至企业微信群机器人，或通过已连接的个人微信网关通知绑定的扫码创建人。微信通知需要有效连接和已建立的会话上下文。企业微信结果推送与消息网关的双向遥控是不同功能。

调度器随应用运行，关闭应用后不会作为独立系统服务继续调度。需要定时执行时，应保持电脑唤醒、应用运行，并确认网络和所需程序可用，不保证任意停机期间的任务都能补跑。

**自动调度中的 WokBee 执行属于无人值守路径，使用自动批准策略，不会逐项等待桌面审批。** 仅安排已审查、可控的项目和脚本。

## 消息网关：手机遥控项目

在 **AIConfig → 消息网关** 配置微信 iLink 或飞书，可同时启用不同频道，并为各频道绑定默认项目。

- 配置允许列表后，授权账号可以发送消息驱动本地 WokBee。
- 支持 `#help`、`#list`、`#new 描述`、`#run` 等指令；使用 `@项目ID` 指定项目。
- 允许列表为空时也拒绝请求，管理指令同样受允许列表约束。
- 执行记录同步到桌面项目时间线，手机接收执行结果和需要澄清的问题。

网关依赖本机应用持续运行和频道连接。**网关触发的项目执行采用无人值守自动批准策略**，不能把桌面审批弹窗当作该路径的安全屏障。只绑定可信账号，并控制可执行项目、附加目录和凭据范围。

## 共享能力与设置

AIConfig 的共享设置包括厂商设置、AI 角色、TokBee 设置、系统运行设置、WokBee 设置、DeziBee 设置、全局记忆、原子记忆、Skills、凭据库、MCP 和消息网关。

| 能力 | 说明 |
| --- | --- |
| 全局记忆 | 一份可编辑的共享规则文档；AI 提交的更新建议仍需用户确认 |
| 原子记忆 | 可按需查询和维护的条目，用于保存可复用的信息 |
| 会话记忆 | WokBee 从项目事件日志推导轮次记录，旧 Markdown 会话记忆保留兼容读取 |
| 项目经验 | 项目内沉淀的处理经验，与共享记忆分别管理 |
| Skills | 管理可复用技能目录，项目可保存所用技能的快照 |
| MCP | 配置外部工具服务器；启动命令、运行时和服务凭据需自行准备 |
| 凭据库 | 本机账号密码保险箱，可向执行子进程注入对应凭据环境变量 |

运行超时、终端与运行环境等系统参数集中在系统运行设置中，业务工作目录和模式参数分别在 WokBee、DeziBee 设置中管理。

## 数据位置与备份

默认应用数据目录为 `~/.wokbee/`，Windows 通常对应 `%USERPROFILE%\.wokbee\`。历史 `~/.tokbee/` 数据有兼容迁移逻辑，请勿在确认迁移结果前直接删除。

| 位置 | 内容 |
| --- | --- |
| `~/.wokbee/config.json` | 应用、运行及业务设置 |
| `~/.wokbee/providers.json` | 厂商和模型配置、API Key 持久化数据 |
| `~/.wokbee/chats.json`、`attachments/` | TokBee 会话与附件 |
| `~/.wokbee/autobee.json` | 定时任务数据 |
| `~/.wokbee/memory.sqlite3` | 共享记忆数据 |
| `~/.wokbee/skills/` | 默认技能目录 |
| `~/.wokbee/vault/` | 凭据保险箱数据 |
| `~/.wokbee/logs/` | 应用日志 |
| WokBee、DeziBee 的工作根目录 | 项目、需求、上传资料及产物 |

备份前关闭应用，再同时备份应用数据目录和实际配置的业务工作目录；仅复制源码不能备份业务数据。

API Key 优先使用系统凭据管理器保存的主密钥加密；系统凭据管理器不可用或加密失败时，当前实现可能降级为明文保存。聊天、项目文件和普通配置也并非整体加密。请将整个数据目录视为敏感数据。

凭据库的加密文件依赖操作系统中的主密钥；复制文件到另一台电脑不保证能解密，应事先确认恢复方式或准备重新配置凭据。模型请求会将相关对话、附件或工具结果发送给选定服务，本地存储不代表完全离线。

## 源码架构

```text
BeeHive/
├── main.py                       # 源码启动入口
├── start.vbs                     # Windows 无控制台启动器
├── pyproject.toml                # 包信息、依赖和资源声明
├── requirements.txt              # 依赖安装清单
└── src/beehive/
    ├── __main__.py               # 包入口
    ├── app/                      # Application、窗口壳、导航、服务注册与生命周期
    ├── common/                   # 通用 IO、进程、错误分类、UI 主题与公共组件
    ├── system/                   # 模型、Agent、记忆、凭据、运行环境、Skills、MCP 等
    └── features/
        ├── tokbee/               # 日常对话
        ├── wokbee/               # 项目、执行、管线、经验与网关业务
        ├── autobee/              # 定时任务
        └── dezibee/              # 需求与原型
```

`ServiceRegistry` 集中创建和复用核心服务；界面层组织交互，业务能力按功能划分，公共 UI 与基础能力放在 `common/`，跨业务系统能力放在 `system/`。调整功能时应先复用已有服务、样式和组件，避免在页面中复制持久化或执行逻辑。

## 开发与验证

本仓库按源码发布策略忽略 `docs/`、`tests/`、虚拟环境、本地配置、数据库、日志、代码索引和构建产物。**全新克隆不包含本地文档和测试套件。**

在维护者持有完整本地测试目录的工作副本中，可以运行：

```powershell
# 完整离线验证
.\.venv\Scripts\python.exe -B tests/run_full_suite.py

# 仅运行 unittest 回归
.\.venv\Scripts\python.exe -B tests/run_isolated.py run_tests.py
```

隔离入口将测试用户目录和临时数据放在 `tests/.tmp/`，使用内存凭据后端；报告和截图位于 `tests/artifacts/`，缓存位于 `tests/.cache/`。测试使用 `-B`，避免向源码目录写入字节码缓存。

完整入口涵盖回归、结构与导入检查、依赖检查、JavaScript 语法及 Qt 窗口和网页冒烟。离线验证不等于外部模型、消息发送、真实 MCP 服务或全部界面交互已验收；截图仍需人工查看。

## 常见问题

**双击启动没有窗口。** 先确认 `.venv\Scripts\pythonw.exe` 存在，再使用控制台启动命令检查错误。安装依赖与启动应使用同一个虚拟环境。

**模型不出现在选择器中。** 确认厂商已添加、模型已拉取或手动录入并启用；检查模型 ID、Host、协议及默认模型配置。

**API 报鉴权、额度或上下文错误。** 核对账号、Key、服务地址和上下文配置。应用对部分瞬时错误提供分类重试，但鉴权或额度问题通常需要修改配置或处理服务账号。

**命令或脚本找不到程序。** 在系统运行设置检查环境探测结果，以及 Python、Node.js、PowerShell 和外部命令的路径；安装 Python 依赖不会自动安装所有外部工具。

**定时任务或手机遥控没有执行。** 确认应用仍在运行、电脑没有休眠；定时任务需启用，网关需连接成功、配置允许列表并绑定有效项目。

**升级后出现旧目录。** 旧项目和旧数据保留兼容读取路径。先备份再检查，不要把旧目录直接当作缓存删除。
