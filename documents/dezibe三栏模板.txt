请为当前dezibee项目建立一个“原型设计工作台模板”。

注意：

这里不是要求你设计某一个具体业务页面,而是建立一个框架。

我要建立的是一个可复用的“导航+原型 + PRD”容器，Dezibee 会在不同的需求中都可以用这个容器中自由创建不同业务的高保真原型和prd页面。

你的任务是建立“框架”,"系统能力"和"能力使用说明,可以理解为SKILLS",。

========================
一、整体工作区
========================

采用三栏结构：

┌──────────┬──────────────────────────┬──────────────┐
│ 导航栏    │       原型画布            │     PRD      │
│          │                          │              │
│          │     AI自由创建原型         │ AI生成说明    │
│          │                          │              │
└──────────┴──────────────────────────┴──────────────┘

三栏是整个模块的固定骨架。

但是三个区域内部的具体内容必须由 dezibee 根据当前需求生成。

========================
二、导航栏
========================

导航栏负责管理“原型项目/页面/场景”。

它至少需要支持能力有：

- 页面列表
- 页面分组-多级菜单
- 页面切换
- 当前页面状态
- 页面新增
- 页面删除
- 页面重命名
- 页面排序

导航栏不负责展示详细 PRD。

它只负责帮助用户快速找到原型页面。

DeziBee 可以根据业务自行决定：

一个页面包含几个原型页面；
是否拆分页面；
是否建立多级分组；
框架不要限制 dezibee。
========================
三、原型画布
========================

这是整个模块的核心。

中间区域不是普通网页，而是一个“自由画布”。

必须支持：

- 无限/大尺寸画布
- 上下左右平移,快速定位原点
- 缩放
- 原型卡片自由移动
- 多个原型卡片同时存在
- 原型卡片选中
- 原型卡片聚焦
- 原型卡片之间建立关系
- 自动适应全部内容
- 聚焦当前原型

 dezibee可以在画布中自由创建：完整页面d的原型卡片.不要规定  dezibee 必须创建哪些类型。

由 dezibee根据需求判断什么值得成为独立原型。

核心原则：

“一个需要开发明确理解的独立视觉/交互状态，可以成为一个独立原型节点。”

========================
四、原型卡片
========================

每个原型卡片都是画布中的一个独立节点。

原型节点至少拥有：

- 唯一 ID
- 名称
- 类型
- 位置
- 尺寸
- 原型内容
- 所属页面
- 对应 PRD信息,如位置等
- 状态信息

原型内容使用真实 HTML/CSS/JS 实现。

不要使用图片模拟页面。

这样浏览器预览时可以真实展示交互效果。

AI 可以自由决定原型尺寸和内部布局。

框架只负责承载。

========================
五、原型卡片之间的关系
========================

支持原型卡片之间建立交互关系。

例如：

卡片A
↓ 点击按钮
卡片B
↓ 选择某项
卡片C。

关系至少可以包含：

- 来源
- 目标
- 触发行为
- 条件
- 说明

AI 可以根据业务需求自由建立流程。

连接线主要用于让开发人员理解：

“什么操作会导致什么状态”。

========================
六、PRD区域
========================

右侧是独立的长文档区域。

它不是普通信息面板。

它应该能够容纳非常长的 PRD。

PRD 内容完全由 AI 根据业务需求生成。

框架只提供文档容器、章节、目录、定位和联动能力。

不要写死 PRD 模板。

但是至少应该能够表达每个原型卡片：

- 页面设计
- 页面结构
- 功能
- 元素
- 交互
- 业务规则
- 状态
- 异常
- 页面跳转
- 数据/API
- 其他开发所需要的信息

具体章节由 AI 自由决定。

========================
七、原型与PRD双向关联
========================

这是系统必须具备的核心能力。

原型和 PRD 必须建立唯一关联。

点击原型：

→ PRD自动定位到对应内容
→ 对应章节高亮

点击 PRD 中的原型引用：

→ 原型画布自动移动到对应原型
→ 原型节点高亮

不要通过名称匹配。

必须使用唯一 ID 建立关联。

========================
八、 dezibee自由创作原则
========================

框架提供的是：

“画布能力 + 原型承载能力 + PRD承载能力 + 双向定位能力”。

 dezibee负责：

- 创建页面
- 创建原型
- 决定原型数量
- 决定原型类型
- 决定原型位置
- 创建交互关系
- 创建 PRD
- 修改原型
- 修改 PRD
- 建立原型和 PRD 的关联

========================
九、浏览器预览
========================

最终通过浏览器预览。

不要在软件内部嵌入浏览器。

调用系统默认浏览器打开生成的 HTML 原型。

浏览器中的内容应该是一个独立的 Prototype Workspace。
