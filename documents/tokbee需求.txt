你现在要在当前 **WokBee** 项目中新增一个完整的 **DeziBee 产品设计模块**。

DeziBee 是 WokBee 现有体系中的一个一级模块。

当前已有：

* **TokBee**：AI 对话
* **WokBee**：Agent / 工作执行
* **AutoBee**：定时任务
* **DeziBee**：AI 产品设计 / 原型设计 / PRD 工作台

DeziBee 必须复用当前 WokBee 的 **Python + LangChain + Agent + Skill + Tool + Workspace** 架构，不要重新设计一套 Agent Framework。

---

# 一、DeziBee 的核心定位

DeziBee 是一个：

> **AI 产品设计工作台**

核心流程：

```text
创建需求
    ↓
用户与 Agent 对话
    ↓
Agent 理解产品需求
    ↓
生成 / 修改 HTML Demo
    ↓
生成 / 修改 PRD
    ↓
调用系统默认浏览器预览
    ↓
用户继续反馈
    ↓
Agent 持续修改 Demo + PRD
```

最终每一个需求都形成一个独立的：

```text
需求
+
Agent 交互记录
+
HTML/CSS/JS Demo
+
PRD
```

---

# 二、非常重要：不要在 WokBee 内嵌浏览器

**DeziBee 不允许内嵌浏览器。**

不要引入：

* WebView
* Chromium 内嵌
* Electron Browser
* Qt WebEngine
* 内置 iframe 浏览器
* 任何需要在 WokBee UI 内显示完整浏览器的方案

DeziBee 的「预览」功能必须：

> **启动/打开本地 Demo 地址，并调用操作系统默认浏览器进行预览。**

例如：

```text
DeziBee
   ↓
Preview Server
   ↓
http://127.0.0.1:xxxx/需求ID/
   ↓
Windows 默认浏览器
```

Windows 下优先使用 Python 标准能力或项目已有能力打开默认浏览器。

例如可以使用：

```python
webbrowser.open(url)
```

但先检查项目现有实现，优先复用。

# 四、右侧工作区结构必须固定

工作区按照以下四个区域设计：

## 1. 需求信息区

展示当前需求的基本信息。

至少包括：

```text
需求名称
需求ID
需求状态
需求描述
创建时间
更新时间
```

可以根据现有 UI 风格进行合理布局。

这里的定位是：

> 当前正在处理什么需求。

---

# 五、交互记录区

这里是用户与 DeziBee Agent 的主要工作区域。

需要保留完整的 Agent 交互记录。

例如：

```text
用户：
帮我设计一个贷款首页。

AI：
我会先设计首页的信息架构，然后生成可交互 Demo。

AI：
已经完成：
- 首页 HTML
- CSS
- JS
- PRD

用户：
把额度区域改得更加突出。

AI：
已修改首页额度区域，并同步更新 PRD。
```

交互记录应该与当前需求关联。

不要把它设计成一个全局聊天窗口。

核心关系：

```text
需求
  ↓
交互记录
  ↓
当前设计上下文
```

---

# 六、功能区

交互记录区下面提供固定功能区。

必须至少包括：

```text
[预览]
[总结上下文]
[另起对话]
[AI模型选择]
```

## 1. 预览

点击后：

```text
检查当前 Demo
      ↓
启动/确认 Preview Server
      ↓
生成当前需求的本地 URL
      ↓
调用系统默认浏览器
      ↓
打开 Demo
```

例如：

```text
http://127.0.0.1:xxxxx/{需求ID}/
```

不要在 WokBee 内显示浏览器。

---

## 2. 总结上下文

用于解决长期对话 Context 越来越大的问题。

点击后让 Agent：

```text
历史交互记录
+
当前需求
+
当前 Demo 状态
+
当前 PRD
+
当前设计决策
```

整理成一个结构化的上下文摘要。

例如：

```markdown
# Design Context

## 产品目标

...

## 当前页面

...

## 已确定设计

...

## 已实现功能

...

## 页面结构

...

## 业务逻辑

...

## 当前 Demo 状态

...

## 后续待处理

...
```

以后新的 Agent 对话可以优先使用这个 Context，而不是把全部历史消息无限塞入上下文。

但是：

> **总结上下文不是删除历史记录。**

原始交互记录仍然保留。

---

# 七、另起对话

「另起对话」用于在当前需求下创建一个新的 Agent Conversation。

例如：

```text
需求：首页

Conversation 1
    ↓
设计首页

Conversation 2
    ↓
重新讨论首页视觉

Conversation 3
    ↓
讨论首页业务逻辑
```

这些对话都属于同一个需求。

但是新的 Conversation 应该能够继承：

```text
需求信息
+
当前 Demo
+
当前 PRD
+
最新 Context Summary
```

因此：

> 另起对话 ≠ 创建新需求。

---

# 八、AI 模型选择

工作区功能区提供：

```text
AI模型： [当前模型 ▼]
```

模型列表和模型配置必须复用 WokBee 当前已有的 AI Provider / Model 配置体系。

不要在 DeziBee 中重新实现一套 API Key / Provider 管理系统。

DeziBee 只负责：

> 选择当前设计任务使用哪个 AI 模型。

# 九、用户输入区

最底部是用户输入区。

支持：

* 多行输入
* Enter / Ctrl+Enter 根据现有 WokBee 规范发送
* 发送消息
* Agent 执行状态
* 错误提示

例如：

```text
┌──────────────────────────────────────────────┐
│ 把首页的借款按钮移动到额度区域下面，并增加... │
│                                              │
└──────────────────────────────────────────────┘
                         [发送]
```

# 十、Demo 文件管理

这是 DeziBee 的核心数据规则。

**每创建一个需求，就必须在 DeziBee 工作文件夹下面创建一个以「需求ID」命名的子文件夹。**

例如全局配置：

```text
工作文件夹：
D:\WokBee\DeziBee
```

创建需求：

```text
需求ID：
REQ-20260910-001
```

自动创建：

```text
D:\WokBee\DeziBee\
└── REQ-20260910-001\
```

该需求产生的所有 Demo 文件都必须放到这里。

例如：

```text
D:\WokBee\DeziBee\
└── REQ-20260910-001\
    ├── index.html
    ├── pages\
    │   ├── home.html
    │   ├── login.html
    │   └── profile.html
    ├── css\
    │   └── style.css
    ├── js\
    │   └── app.js
    ├── assets\
    │   └── ...
    └── prd\
        ├── home.md
        ├── login.md
        └── profile.md
```

实际目录结构可以根据实现需要调整。

但必须满足：

> **需求ID是 Demo 工作目录的唯一标识。**

# 十一、工作文件夹配置

DeziBee 的通用设置不要放在 DeziBee 页面里面。

WokBee 已经存在专门的全局设置模块。

在现有全局设置中增加：

```text
AIConfig
└── DeziBee 设置
```

不要创建独立的 DeziBee Settings 页面。

---

# 十二、AIConfig → DeziBee 设置

第一个设置项：

```text
DeziBee 工作文件夹
```

例如：

```text
工作文件夹
[D:\WokBee\DeziBee             ] [选择文件夹]
```

该设置负责：

```text
DeziBee 工作文件夹
        ↓
创建需求
        ↓
创建 {需求ID} 文件夹
        ↓
Demo / PRD / Assets 全部存储在其中
```

需要考虑：

* 路径不存在时是否自动创建
* 路径是否可写
* Windows 路径处理
* 路径变化后的行为
* 默认工作文件夹
* 配置持久化
* 错误提示

具体配置机制必须复用当前 WokBee 的 AIConfig / 全局配置体系。

# 十三、Demo 的三层内容结构

每个 DeziBee Demo 必须包含三个概念层。

## 第一层：导航

负责多个页面之间的关系。

例如：

```text
首页
产品
订单
我的
```

如果是多页面 Demo：

```text
首页
 ↓
产品
 ↓
详情
 ↓
订单
```

Agent 需要维护页面之间的导航关系。

---

## 第二层：页面

真正运行的 HTML Prototype。

必须尽可能支持真实交互：

```text
点击
跳转
表单
弹窗
展开/收起
状态变化
业务流程
```

目标不是生成一张静态网页截图。

目标是：

> **可运行、可点击、可演示的产品原型。**

---

## 第三层：PRD

每个页面都应该有对应的需求说明。

包括：

```text
页面结构
功能说明
元素说明
交互说明
业务逻辑
状态变化
异常状态
```

PRD 与 Demo 必须保持关联。

当 Agent 修改页面功能时，需要根据实际情况同步修改 PRD。

# 十四、Agent 的职责

DeziBee Agent 不是普通 Coding Agent。

它同时承担：

```text

原型设计师
PRD分析师
前端原型工程师
```

Agent 应该能够：

```text

↓
拆解页面
↓
设计页面结构
↓
设计交互
↓
生成 HTML/CSS/JS
↓
生成 PRD
↓
运行/检查 Demo
↓
根据用户反馈修改 Demo
↓
同步修改 PRD
```

# 十七、必须支持的完整闭环

最终必须真正跑通下面这个流程：

```text
用户进入 DeziBee
        ↓
创建需求
        ↓
输入需求名称 / 描述
        ↓
生成需求ID
        ↓
在 DeziBee 工作文件夹创建：

{需求ID}/
        ↓
进入需求工作区
        ↓
用户与 Agent 对话
        ↓
Agent 分析需求
        ↓
Agent 创建 Demo 文件
        ↓
Agent 创建 PRD
        ↓
用户点击「预览」
        ↓
启动/确认本地 Preview Server
        ↓
调用系统默认浏览器
        ↓
浏览器打开 Demo
        ↓
用户返回 WokBee
        ↓
继续和 Agent 对话
        ↓
Agent 修改 Demo
        ↓
Agent 修改 PRD
        ↓
再次点击预览
        ↓
浏览器看到最新结果
```

# 二十、最终验收标准

DeziBee MVP 必须满足：

* [ ] WokBee 可以进入 DeziBee
* [ ] 可以创建需求
* [ ] 创建需求后自动生成需求 ID
* [ ] 自动在配置的工作文件夹创建 `{需求ID}` 子目录
* [ ] 所有 Demo 文件存放在该目录
* [ ] 可以与 Agent 对话
* [ ] Agent 可以生成真实 HTML/CSS/JS 文件
* [ ] Agent 可以生成 PRD
* [ ] Demo 支持多页面
* [ ] Demo 支持导航
* [ ] Demo 支持基本交互
* [ ] 点击预览可以调用系统默认浏览器
* [ ] WokBee 本身不内嵌浏览器
* [ ] Agent 修改文件后可以重新预览
* [ ] 可以总结上下文
* [ ] 总结不会删除原始交互记录
* [ ] 可以另起 Conversation
* [ ] 新 Conversation 可以继承当前需求/Demo/PRD/Context
* [ ] 可以选择 AI 模型
* [ ] DeziBee 工作文件夹位于 `AIConfig → DeziBee 设置`
* [ ] 不重复实现全局 AI Provider / API Key 配置
* [ ] 复用 WokBee 当前 LangChain / Agent / Skill / Tool 架构

---

# 二十一、最重要的开发原则

不要为了完成 DeziBee 而重新架构 WokBee。

不要先做一个复杂的大而全系统。

首先实现：

> **需求 → Agent → Demo + PRD → 默认浏览器预览 → 修改 → 再预览**

这个最小闭环。

所有实现都必须优先考虑：

**复用现有能力 > 新增简单能力 > 引入新框架**

现在开始扫描项目并实施。

先理解现有架构，然后直接开始编码，不要停留在方案讨论阶段。
