# WokBee 项目目录调整方案

状态：已整理产品方案，尚未实施目录重构。
范围：仅新项目，不迁移、清理或改写旧项目；不涉及 DeziBee 目录调整。

## 一、目录结构

```text
工作目录/
└─ 项目ID/
   ├─ archives/
   │  └─ arch_时间戳/
   ├─ uploads/
   ├─ output/
   ├─ memory/
   │  ├─ events.jsonl
   │  ├─ exp_时间戳.md
   │  ├─ pipeline.json
   │  ├─ 用到的脚本.py
   │  ├─ 脚本所需配套文件
   │  └─ 技能名称/
   │     ├─ SKILL.md
   │     └─ 技能配套文件
   ├─ .project/
   │  ├─ project.json
   │  └─ Agent.md
   ├─ 临时脚本
   ├─ 参考文件
   └─ 中间材料及执行反馈
```

1. 项目目录：创建项目时生成项目 ID，以 ID 命名文件夹。项目名称保存在配置中，重命名项目不改变目录名。
2. archives/：保存当前项目的历史归档；每次归档建立独立快照。Agent 禁止读取或使用归档材料作为任务数据源。
3. uploads/：保存用户上传的原始材料和脚本，普通归档保留；上传不移动外部原文件，同名增加后缀避免覆盖。
4. output/：保存最终交付物。最终成果必须写入或复制到这里；中间文件、日志和工具回调不作为最终成果交付。
5. memory/：保存会话事件、项目经验、运行管线、复用脚本、技能和复跑配套材料。经验和脚本直接存放，不设 experiences/、scripts/ 分类子目录；每个技能保留自身目录结构，直接位于 memory/ 下。
6. .project/：保存系统维护的项目配置，以及用户维护的项目行为规则。
7. 项目根目录：保存执行中的临时脚本、参考文件、中间材料及执行反馈。需要长期复跑的材料在经验总结时复制到 memory/；最终成果放到 output/。
8. 新项目不再建立 workspace/、scripts/、runs/、deliverables/、memory/experiences/ 或 uploads/references/ 分类目录；允许材料自身必要的配套子目录。

## 二、启动 Agent 时的目录说明

1. 每次运行、聊天、设计及恢复 Agent 时，在系统提示词中明确注入当前项目 ID、真实绝对地址、虚拟根地址、路径映射和执行命令的默认工作目录。
2. 虚拟根地址 `/` 只映射当前项目，不表示整台电脑；文件工具使用虚拟路径，execute 使用真实路径或相对于项目根目录的路径。项目外访问保持现有授权边界。
3. 系统提示词必须说明上面每个目录的作用、允许写入的内容，以及哪些目录由系统维护；不得仅列出目录名。
4. 不将 BeeHive 源码目录或软件启动目录误当成 Agent 项目目录。

```text
项目 ID：<当前项目ID>
项目绝对地址：<当前工作目录>\<项目ID>
项目虚拟地址：/
execute 默认工作目录：<当前工作目录>\<项目ID>
/output/报表.xlsx 对应 <当前工作目录>\<项目ID>\output\报表.xlsx
```

## 三、项目规则 Agent.md

1. 创建新项目时生成空的 `.project/Agent.md`；已存在时不覆盖、不清空。
2. 用户可以填写当前项目的行为规则。每次启动 Agent 或开始新一轮交互时读取非空内容，以“用户自定义项目规则”加入系统提示词；正在执行中的一轮不动态替换规则。
3. 规则适用于运行、聊天和设计模式，普通归档保留该文件。
4. Agent 可以读取，但默认不能自行改写。用户规则不能绕过系统安全、目录访问和审批限制。
5. 此文件属于运行时项目；BeeHive 源码仓库的开发指令仍使用根目录 `AGENTS.md`，两者用途不同。

## 四、会话记忆与事件记录

1. 取消独立 `session_memory.md`；会话记忆、时间线和执行过程统一使用 `memory/events.jsonl`，不重复保存另一份事件日志。
2. 保留 JSONL 追加方式：每条事件是一行独立 JSON，由系统直接追加到文件末尾。文件本身不采用需要整体重写的嵌套 JSON 数组；界面和记忆工具读取时按轮次组织为“轮次 → 事件”。
3. 每条记录包含轮次编号、轮次唯一 ID、轮次开始时间、轮次类型、用户输入或项目目标，以及事件序号、事件 ID、事件时间、事件类型和内容。字段顺序中 `seq` 位于 `id` 前；事件序号在每轮内从 1 递增。
4. 轮次类型区分运行、聊天、设计。开始一轮时记录开始事件，结束时记录结束事件；等待审批及其恢复属于同一轮，不创建重复轮次。
5. 事件类型区分用户输入、AI 回复、工具调用、工具返回、审批、错误和系统通知。调用及返回需要保留工具名称和关联调用 ID，以便追踪。
6. JSONL 的字段顺序用于可读性，实际逻辑依赖字段名、轮次 ID 和序号，不依赖 JSON 对象的键顺序。
7. 同一项目并发写入须串行分配序号并追加；保存后刷新缓冲。异常中断产生不完整末行时，读取应保留已完成记录并报告异常，不能破坏整份历史。
8. 系统维护事件文件，Agent 通过受限记忆读取工具查询最近轮次、指定轮次、关键词或范围，不直接改写。避免每轮把全部历史发送给 AI。
9. 系统写入、排序和截断均通过本地代码完成，不调用 AI、不消耗 AI Token；模型读取记忆或生成经验时才产生对应 Token 消耗。
10. 事件中已知凭据需脱敏后保存，延续现有安全规则。

以下为一行事件展开后的示例；实际文件每条记录占一行：

```json
{
  "round": 1,
  "round_id": "唯一轮次ID",
  "round_started_at": "2026-10-15T10:00:00+08:00",
  "round_type": "run",
  "user_input": "",
  "goal": "生成销售报表",
  "seq": 2,
  "id": "唯一事件ID",
  "time": "2026-10-15T10:00:01+08:00",
  "type": "tool_result",
  "tool_name": "read_file",
  "call_id": "关联工具调用ID",
  "content": "工具返回内容",
  "truncated": false,
  "original_chars": 120
}
```

## 五、工具返回记录截断

1. 以字符数计，不以字节或 Token 计。工具返回不超过 4,000 字符时完整保存。
2. 超过 4,000 字符时，保存前 2,000 和后 2,000 字符，中间插入明确省略标记；另存 `truncated=true` 和原始长度 `original_chars`。省略标记本身不计入保留的 4,000 字符。
3. 截断仅用于事件持久化内容，不截断工具实际执行结果、原始产物文件或交给当前 Agent 的原始返回。
4. 不在事件其他字段中重复保存被省略的完整工具正文，否则无法达到控制记录大小的目的。
5. 此规则针对工具返回，不将其直接扩展成用户消息和 AI 回复的统一截断规则。

## 六、经验、脚本、技能与管线

1. 经验通过专用经验工具或系统经验整理流程保存为 `memory/exp_时间戳.md`，每次新建版本，不覆盖旧经验；运行默认使用最新经验。
2. 总结经验时，必须将实际用到且复跑需要的脚本保存到 memory/，同步保存技能及脚本必需的配套文件；不只记录脚本名或失效的临时路径。
3. 上传脚本原件保留于 uploads/；总结经验时可以复制复跑所需版本到 memory/，保持原件不变。
4. 管线统一位于 `memory/pipeline.json`，以项目根目录为路径基准，引用 `memory/脚本.py` 等真实文件。脚本和配套文件保存、路径验证成功后，再提交管线。
5. 根据新的脚本位置调整运行器、脚本模板、技能路由和文件访问校验，避免沿用“scripts/ 的上一级就是项目根”的旧假设。
6. 普通归档保留 memory/；清空经验时归档并清理经验、管线、复用脚本和技能，但保留 `memory/events.jsonl` 会话记录。

## 七、写入与交付规则

1. 新生成材料遇到同名文件时增加时间或序号后缀；明确修改既有文件时才覆盖。系统固定配置和管线通过专用流程更新。
2. 最终文件必须位于 output/，保留需要的格式、名称和配套结构；任务结束前检查实际文件，并在回复或界面中提供交付路径。
3. 取消把整个工作区自动复制为成果的做法，只将当前任务真正需要交付的文件放入 output/。
4. 固定配置与管线采用原子替换保存；事件采用追加保存，不把两种写入策略混用。

## 八、归档与保留

1. 每次归档在当前项目 archives/ 下生成独立 `arch_时间戳/`，同名追加序号，保持现有快照和清单逻辑。
2. 普通归档复制 output/ 和根目录本轮材料，保留相对路径；对应材料复制成功后才清理源内容，复制失败则保留源文件并提示。
3. 普通归档保留 uploads/、memory/ 和 .project/，不清空会话事件或用户项目规则，也不归档 archives/ 自身。
4. 长期复跑资源已集中到 memory/，根目录材料按本轮材料处理，不再需要通过额外 files.json 区分根目录脚本与成果。
5. `MANIFEST.md` 记录归档时间、已归档材料和保留项。普通 `arch_*` 存档最多保留 50 份，超过后删除最旧存档。
6. 保持现有归档入口；本方案不新增“每次启动必定自动归档”的触发规则。

## 九、实施范围与验收

1. 统一修改目录常量、项目配置及事件定位、记忆查询、经验存储、脚本模板、管线运行、技能挂载、提示词、上传、交付物入口和归档清理逻辑。
2. 不实现旧项目目录迁移或兼容重写；实施前需确保调整后的新项目规则不会误清理旧项目。
3. 验收覆盖新项目目录创建、Agent 路径说明、空及非空 Agent.md、JSONL 追加与轮次恢复、4,000/4,001 字符边界、脚本/技能复跑、最终成果交付、普通归档和清空经验。
4. 所有测试脚本、夹具、临时项目、日志、报告、截图及缓存放在 BeeHive 源码仓库 tests/ 下，不在源码根目录生成测试残留。
5. 本文为后续实施依据，不表示上述目录重构已经完成。
